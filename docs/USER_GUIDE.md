# WeaveGrid 使用手册

本机运行的中文小说工作台。自动生成经纬结构，以完整状态图管理倒序大纲、正序正文、跨章修订和人工审核。

## 启动

在项目根目录运行 `./启动.sh`，打开 <http://127.0.0.1:8731>。首次启动没有可执行文件时自动构建；之后运行只需要可执行文件、Bash 和 Python 3。构建需要 Go 1.27.1+、Node.js 22.12+ 与 npm。当前入口使用 Unix 文件锁，支持目标为 Linux/macOS，Windows 请使用 WSL2。

首次构建：`make build`。更改源码后同样执行此命令；启动脚本不自动检测源码变化。程序输出为 `bin/weavegrid`。数据保存在 `data/novelflow.db`（为兼容旧版保留文件名），采用 SQLite WAL；备份时先停止服务并复制整个 `data/` 目录。

可用 `./启动.sh --addr 127.0.0.1:8732 --data /其他路径` 指定地址和数据目录。默认仅监听本机，同一数据目录只允许一个工作台进程。界面不依赖外部字体服务；不安装 Node.js 也能直接运行已构建的程序。

## 使用顺序

1. 新建项目，填写章节数与随机种子，生成预览并采用；也可以导入完整经纬 JSON 或 `[[埋线章,回收章],...]`。
2. 在“模型”分别配置大纲、正文、统筹、核查和摘要模型。大纲、正文、统筹默认使用 Kimi K3。人物、世界观与设定随创作形成，不需要填写笔记页。
3. 点击流程节点，在右侧“提示词”编辑公共提示词或 AI 子步骤提示词。保存、预览、恢复默认、从历史版本载入均在这里完成。
4. 选择“后向编纲”，开始执行。默认每章到 C2 弹窗，填写或确认本章创意；也可打开顶部“统筹 AI”，由统筹处理创作输入、必要资料、关键取舍与审核。
5. 所有大纲完成后，按正序通读，确认最终审核。再选择“前向写作”；直接使用已配置的正文模型，不进行文风评测或确认。
6. 在“写作”编辑内容、选择历史版本、保存回滚版本，或导出 Markdown/TXT。在“记录”查看请求、输入版本、实际提示词和输出。

默认中文提示词位于 `internal/workbench/workflow.go` 的 `promptDefaults`，在界面保存的修改会独立保留版本。

### 黑夜模式与自动统筹

右上角太阳/月亮按钮切换日间与黑夜模式，覆盖编辑器、弹窗、流程画布与经纬双轴图。首次跟随系统主题，手动选择后保存在当前浏览器，刷新仍保留。

“模型”新增独立的“统筹”角色。开启“让统筹 AI 接管创作弹窗”或顶部“统筹 AI”后，连续运行中的 C2 创意确认、B8 补充问题、F7 修订取舍和 H5 审核交给该模型。已停在这些输入关卡的连续运行会继续；暂停、终止、检查点回退、作品归档等管理动作仍由用户控制，单步模式仍保留人工关卡。统筹不会自动启动下一种运行方向。

统筹从章节的叙事功能、人物变化与因果出发安排建议，逐条判断审核意见，不以全部接受/拒绝代替审核。用户必留创意原样保留，统筹建议和决定标明来源，不冒充人工提交。在模型页填写“给统筹的长期要求”，并展开“统筹记忆”查看近期决定、摘要和压缩次数；完整调用与原始日志在“记录”中保留。

记忆随作品持久化，在章节、运行方向、服务重启及检查点中继承。参考 DeepSeek Harness 的 `compaction-basic`：将较早完整轮次压缩成摘要，保留近期尾部，只有摘要有效且确实缩小后才连同新决定原子提交；失败或取消不会覆盖原记忆。采用应用现有的字数预算，给创作材料和纠错留余量，不依赖 dsh 的运行时或 tokenizer。

### 大纲里的伏笔提示

新生成的大纲分为“事件要点”和“伏笔提示”两部分。每条提示都标明伏笔编号、埋线章、回收章和提醒章，直接保存在大纲原文里，随大纲一起审核、编辑、回滚和导出。例如：

```markdown
## 事件要点

本章事件及因果……

## 伏笔提示

- T001（第12章 → 第50章；提醒第30章）：一件旧物留下未解疑问。
```

提示词要求每条只用一句、不超过50字，越模糊越好；只留铺垫方向，具体情节写到对应章节再形成。程序不按字数裁剪，也不因超过50字反复重写。D4 将提示放入候选后再进入跨章审核；G 保存时只从最终大纲提取索引，不另加隐藏内容。提示不写入人工创意。

创作请求直接读取伏笔两端和提醒章已有的大纲，前向写作还会带入这些章节已写的正文；保留前后各两章材料窗口，不依赖语义检索是否召回。对面章节尚未编写时明确标为待安排，不虚构原文。提示绑定回收章的大纲版本，人工修改提示行后以可见大纲为准。老作品在 D1/E1 按需补齐缺失提示，随后写入本章新大纲；不会批量重写已有章节。

审核与上下文阅读区将事件和提示分开排版；“结构与关联”可直接打开两端章节。提示词新增 `{{foreshadows}}` 变量；D1/E1 的模型调用只在提示缺失时发生，已有提示会直接复用。

大纲输出固定为“事件要点”和“伏笔提示”两部分，任务会列出本章实际允许使用的编号及章号。D4 整理时只返回本章回收的伏笔；相邻章提示仅作参考，本章没有回收项时必须返回 `foreshadows: []`。程序分别校验编号越界、重复、缺项、空提示和 JSON 数组类型；格式错误自动纠正最多 3 次，保留各次请求记录，只重试整理步骤，不重写已有大纲。该约束也随完整请求附加到旧作品及自定义提示词，原有创作要求保留。

### 完整流程画布与手动排布

A–H、J 的 9 个分组、71 个内部步骤放在同一张画布上，后向编纲与前向写作共用这张完整图。拖动分组标题可整体移动流程，拖动内部方框可调整子步骤；只调整显示位置，不改变执行顺序。

- 双击分组、点击“定位”或使用“定位子流程”下拉框可放大查看该流程；“全景”回到整张大图。单击步骤查看状态、输入输出和提示词。
- “专注画布”放大工作区；滚轮缩放，拖动空白处平移，也可启用缩略图。
- 连线使用独立端口和直角通道，避免共用线段；交叉处用断口区分。松开拖动后重新计算走线。
- 移动后自动保存到工作台数据库，浏览器同时保留备份；“保存位置”可手动保存。完整工作流布局在各项目间共用。章节经纬页仅展示关系图，不提供编辑或布局写入入口。
- “布局方案”可导出 JSON 或粘贴布局采用。“自动排布”只重置当前图的位置。代码更新、运行进度变化和切换运行方向不会主动打乱已保存的完整流程布局。

**暂停**立即取消在途请求并保留部分草稿，**继续**重跑被中断的步骤，**终止**结束本次运行。已完成步骤和已采用内容保留。终止后重新开始会依据当前项目进度创建新运行。

运行期间的章节手工修改存为待采用版本，在下一次章节定位或进度调度时进入跨章复查，完成复查后原子采用；C 只交付本次由你确认的创意快照，提交后不会被其他编辑静默替换。提示词与模型配置在下一次请求时采用。页面刷新不停止后台任务；服务重启后等待手动继续。

## 人工输入、作品与回退

- 左上角“作品管理”可以新建、搜索、打开、改名、复制和归档作品。复制保留有效内容、结构、提示词和笔记，不复制运行任务及待采用编辑；有未结束运行时需先结束运行才能归档。
- 笔记页已撤掉。C2 是每章必经的创意关卡；未启用统筹时填写本章或全书创意，区分必留/可选与是否采用。有预存内容也需确认；空创意必须显式勾选“不提供人工创意”。启用统筹后由其提交并单独标注来源。点击 C 查看历次输出。
- 所有操作弹窗提供创作上下文，能查阅任意章的大纲、正文、创意、参考资料、版本引用、结构关系和候选问题。阅读位置与表单独立。收起弹窗保留本次页面的未提交草稿，提交后才保证刷新、重启不丢失。
- 需要输入的节点：**C2** 每章填写或确认创意；**B8** 回答材料检查发现的必要问题；**F7** 处理关键冲突、必留要求与反复修订的取舍；**H5** 处理审核意见并确认通过。侧栏“需要我输入的节点”可随时查看。任意模型节点出错会另弹出处理窗口。
- 每章大纲、正文首次保存成功时分别自动创建检查点，名称为“自动 · 第 N 章大纲完成 / 正文完成”。与章节有效版本及执行位置同一事务提交，不暂停连续写作；包含本轮跨章修订和统筹记忆。回退后从保存后的步骤继续，后续审核仍需正常完成。已有章节不补打历史检查点；修订已完成章节不会重复打点。
- 顶部“检查点 / 回退”可以查看自动检查点，也可手动保存项目有效内容、人工创意及提交记录、提示词、模型配置、候选、执行位置和请求历史。运行中手动保存会先暂停；检查点覆盖整个作品。
- 在检查点列表点击“回退到此检查点”，核对后点击“确认回退”。运行中先暂停；若暂停期间内容变化，界面要求核对后再次确认。回退事务会先建立“恢复前自动备份”，再切换内容、终止旧运行，并从保存位置创建暂停的新运行；已完成/终止的快照保留该状态。点击“继续”或“前进一个小节点”恢复执行。要撤销回退，可回退到那份自动备份。
- 当前节点带明显边框、底色与“当前”标记，等待人工时使用琥珀色。默认“跟随执行”在节点转移时自动聚焦；手动查看其他流程时可关闭。视口移动不会改变手工排列。

## 单步与自动重试

“前进一个小节点”从空闲状态开始或从暂停/失败/待输入状态执行一个内部节点后停住。它与连续运行使用同一套持久化游标，模型节点完成本次生成才停下；批量摘要或核查在单步时一次处理一项。运行中先暂停，再单步。必要的人工选择仍然会阻塞，不能通过单步绕过。

模型调用错误、空输出、截断、JSON 格式/字段校验失败及其他节点执行错误最多自动重试 3 次（初次加重试共 4 次）。网络与服务错误默认间隔 1、2、4 秒，并遵守接口的 `Retry-After`（上限 30 秒）；格式错误将校验原因反馈给模型并立即纠正。网络与格式失败共享同一预算，不叠加多层重试；格式错误只重跑对应解析/核查步骤，不重写已生成的候选。

重试使用独立连接，每次尝试保留独立记录，失败片段不会拼接进新候选。界面显示次数，暂停会取消请求和退避等待。达到上限后保留进度，提示原因并提供“重试当前步骤”；不会无限循环，也不会因统筹已开启而忽略错误。认证错误也会尝试三次，但无效凭据仍需用户修正。

浏览器到本机后台的请求也会重试临时断线，重发沿用同一幂等标识，防止重复建立作品、运行或检查点。版本冲突不会盲目重试。

## 经纬生成

默认 50 章、种子 7：5 个剧情单元、11 个转折节点、58 条伏笔结构记录、47 组去重章节关系、14 个无连线章节。

新生成结构按回收入度划分剧情单元：一章回收的独立伏笔大于 4 条（至少 5 条），就在该章结束当前单元，下一章开启下一单元。同一起止章节的不同伏笔分别计数，提醒和新增关联不计入回收入度。默认 50 章、种子 7 的单元为 1–10、11–17、18–30、31–43、44–50 章。

全书末章强制至少回收 5 条伏笔，不足时只补足差额，优先选尚未连向末章的较近章节；短篇来源不足时允许同一来源设置多条独立伏笔，每条跨度仍至少为 2 章。重新分段后同步更新转折节点所属单元。导入结构和已有作品保留其原有分段。

原算法位于 `internal/workbench/generator/original.py`，权利人已确认可随项目发布，采用项目的非商业许可。`runner.py` 保持原算法的随机序列不变，在结束后确定性补足末章回收入度、按入度重新分段、补齐长跨度提醒，并删除随机事件、线索名称和题材类型。随机内容不会进入项目或模型请求。

生成器限制 3–2000 章；直接导入支持 1–2000 章。已有创作或运行记录时，重新生成应创建新项目。完整结构保留重复起止章节的独立伏笔记录，双轴图分别显示每条伏笔，并按章累计设定和收回数量。最小起止跨度统一为 2 章。

“经纬”页采用上下双轴：上方为伏笔设定轴，下方为伏笔收回轴，每章一个等距刻度。连线从设定章向下连接收回章，小圆点表示对应章节的途中提醒，紫色刻度表示转折章。大纲与正文分别用逐章色带标记实际完成状态，支持倒序编纲和不连续进度。两轴旁的数量柱显示该章设定 / 收回密度，底部全书密度条汇总设定、收回与提醒，可点击快速定位。

可用鼠标拖动、滚轮、触控板或左右按钮横向浏览，调整章节间距；矮窗口可纵向查看，Shift + 滚轮横向浏览。点击刻度选章，悬停或点击连线查看起止与提醒，也可筛选只看选中章。已有的有效新增关联保留为紫色虚线，不计入伏笔数量。经纬图不提供结构修改入口；要使用另一套结构，请新建作品。新建预览可展开全部转折、伏笔起止与提醒，并导出 JSON。

## 模型与检索

大纲、正文、统筹默认使用 OpenCode Go 的 `kimi-k3`，核查与摘要保留 `deepseek-v4.1-flash`，接口为 `https://opencode.ai/zen/go/v1`。Kimi 默认输出上限 16384、思考强度 high，可在模型页单独调整。旧项目中仍采用原 OpenCode 默认模型的大纲/正文会一次性升级；自定义端点及模型保留。“大纲、正文与统筹使用 Kimi K3”按钮可同时设置这三个角色，保存后生效。

凭据引用 `opencode-go` 优先读取 `OPENCODE_API_KEY`，然后读取本机 `~/.local/share/opencode/auth.json` 的同名提供方。凭据值不进入前端、请求记录或导出。

本地 RWKV 可单独配置在“正文”角色：填写兼容 Chat Completions 的地址与模型名，无认证服务的凭据填 `none`；也支持 `env:环境变量名`。文本生成不要求工具调用或结构化输出能力。必须正确返回 SSE 结束标记及 `finish_reason: stop`，截断输出会作为失败候选保留。

关键词检索默认启用，使用 FTS5 trigram 与短词子串匹配。填写可选向量服务后，调用标准 `/embeddings` 接口，使用余弦相似度补充结果；向量按服务配置、内容版本和段落绑定，默认结果只包含当前有效版本。首次启用时按需补建既有内容索引。

正文、大纲、统筹、核查、摘要的模型和参数可以分别设置。文风准备子流程及评测配置已移除，旧项目的文风字段不会再注入创作请求。创作请求上下文超过设置上限时明确报错，不静默截断；可提高上限或减少参考资料。统筹先压缩记忆并分批处理意见，再按预算补充注明摘录的原文；用户要求与待处理意见不会静默丢弃。长篇审核分章正序进行，并提供关联章节原文。

## 执行与版本保证

- 同一项目只允许一个未结束运行；独立核查默认并发 2，修改串行处理。
- 每个请求保存提示词版本、配置快照、引用位置、候选输出和用量。
- 同一批次的正文、大纲、关联和索引原子采用。版本冲突或派生记录重建失败时，保留此前完整版本。
- 段落引用在采用提议前验证。关键取舍、涉及必留创意或证据无法验证的问题交由人工处理。
- 同一目标在一个复查批次内最多自动修订三轮，继续反复时要求人工选择；审核与原文版本绑定，相关原文改变后审核失效。
- 跨章复查先收集本轮问题，普通衔接自动修正，仅未决关键冲突集中询问。章节含必留创意本身不会触发人工取舍；已处理意见在待办区收起，历史决定继续约束后续生成。
- 生成与复查读取前后各两章的已有内容，并补充经纬关联章节。倒序编纲按后两章安排前因和铺垫，不重复后章关键事件；新增候选造成冲突时优先修正新增候选。缺少内容的章节明确标为未生成。
- 终止或完成后，审核待办、数量提示与填写入口一并关闭；旧意见留在运行历史中，不再作为当前待办展示。
- 同章待执行意见合并修订，F9 独立核验是否落实，未通过自动修正，连续三次失败保留候选并报告执行失败；不会仅因模型返回文本就标成已执行。
- 大纲保持简洁事件要点，按情节需要自然增减，不设硬性字数限制或强制压缩。倒序编纲围绕“为了让后续章节的事情自然发生，这之前应该发生什么？”推导本章，章末衔接下一章开头。自定义 D2/F8 提示词可调整表达与篇幅。
- F9 将原文引用与解释分开核验；引用或核验JSON格式错误自动重试最多3次（首次加重试共4次），显示重试进度，不重写候选，不计入内容修订次数。明确发现未落实的要求才回到 F8 修订。
- 暂停和终止先更新执行代次再取消请求，迟到结果无法提交；进程重启后执行尝试标记为中断。
- 调用错误、无效格式和输出截断均最多重试三次；耗尽后保留现场等待处理。结构化解析失败不会被复用为成功请求。

## 接口与开发

后端位于 `internal/workbench/`，浏览器界面位于 `web/src/`。前端构建资源通过 `web/embed.go` 嵌入 Go 程序。

主要接口：`/api/projects`、`/api/structure/preview`、`/api/projects/{id}/prompts/{node}`、`/api/projects/{id}/edits`、`/api/projects/{id}/search`、`/api/runs`、`/api/runs/{id}/control`、`/api/runs/{id}/decisions`、`/api/runs/{id}/attempts`、`/api/runs/{id}/events`。

新增接口：`/api/projects/{id}/copy`、`/api/projects/{id}/notes`、`/api/projects/{id}/notes/{note}`、`/api/projects/{id}/checkpoints`、`/api/projects/{id}/checkpoints/{checkpoint}/restore`、`/api/runs/{id}/input`、`/api/runs/{id}/creative-input`。运行创建接受 `singleStep`，运行控制接受 `step`；运行快照中的 `nextNode` 为下一内部节点。

`/api/workflow` 发布节点、内部连线和各状态可执行操作；前端据此绘制流程与启用按钮。

`/api/layouts/{id}` 独立保存画布位置，使用幂等标识和布局版本防止旧保存覆盖新位置，不修改小说内容版本。

变更请求使用 `Idempotency-Key`；编辑可用 `If-Match` 传入当前资源 revision。事件使用 SSE 递增序号，支持 `Last-Event-ID` 断线续取；首次打开使用 `tail=1` 读取当前快照，避免重放旧状态覆盖新页面。

前端开发：启动后端，再执行 `cd web && npm run dev`。Vite 将 `/api` 转发给本机 8731 端口。

## 验证

- `make test`：Go 行为测试、竞态检查、静态检查、前端类型检查与生产构建。
- `make live-smoke`：显式调用真实 OpenCode，使用独立临时项目完成 Kimi K3 短大纲、短正文、统筹决定、记忆压缩及 DeepSeek 核查；会消耗少量模型额度。
- 如需留存原文，设置 `NOVELFLOW_LIVE_OUTPUT` 为 JSON 输出文件路径；文件包含大纲、正文、核查及实际请求记录，方便人工评读。
- 模拟服务可加 `--ask-input --disconnect-once`，用于验证缺资料弹窗与 EOF 重试。
- `go run ./cmd/smoke-server`：在 8741 端口启动浏览器验收专用模拟模型服务，使用 `artifacts/browser-smoke/` 独立数据库。

模拟服务只用于验收；正式启动入口始终使用真实模型适配器。公开源码不包含本地数据库、创作样本或私人验收记录。开发说明见 [CONTRIBUTING.md](../CONTRIBUTING.md)。
